# Adaptive unit selection for homework print generation

The TypeScript webhook handler no longer dictates which unit a child practices. Instead, the Python agent looks up the child's `current_unit_order` from DynamoDB and delegates to `determine_next_problem` to pick the subcategory, difficulty, and question count. Backward compatibility is preserved: when `params.subcategory` is explicitly provided, the old path runs unchanged. The `category` field saved to the prints table now comes from the recommendation rather than being extracted from an often-empty payload field.

**Watch for:** No error handling around the new DynamoDB read and `determine_next_problem` call (confirmed) — an unreachable table, malformed child record, or recommendation failure surfaces as an unhandled exception rather than a structured error response. Truthiness check on `subcategory` means empty string `""` triggers auto-select rather than the explicit path (likely, minor).

## High-level view

The change shifts unit-selection responsibility from the TypeScript edge (hardcoded `addition_no_carry`) to the Python agent core, closing the loop between the stats system (which unlocks units) and the print generator (which now respects unlocked progress).

The auto-select path has no try/except wrapping. If the children table is unreachable, the child record is malformed, or `determine_next_problem` raises, the exception propagates through `asyncio.run` to the AgentCore framework. Whether that translates to a structured `{"error": ...}` or a transport-level failure determines the user experience.

The test suite covers the happy path and default-value edge cases but doesn't exercise failure modes (DynamoDB errors, missing keys in recommendation dict).

## Error propagation gap in auto-select path

The new code in `handle_generate_print`:

```python
children_table = dynamodb.Table(CHILDREN_TABLE)
child_response = children_table.get_item(Key={"child_id": child_id})
child_record = child_response.get("Item", {})
current_unit_order = int(child_record.get("current_unit_order", 1))

recommendation = determine_next_problem(child_id, current_unit_order)
```

Neither call is wrapped in error handling. `get_item` can raise `ClientError` (permissions, table not found, throttling). `determine_next_problem` queries `LEARNING_STATS_TABLE` internally and does division/comparison on stat values — a malformed stat item (e.g., `accuracy_rate` stored as a string) would raise. The `int()` cast on `current_unit_order` will raise `ValueError` if the stored value is non-numeric.

The TS handler has a `try/catch` that logs and sends a generic error message, so an unhandled exception won't crash the system — but it produces an opaque error rather than the structured `{"error": "..."}` response that the `if (result.error)` branch expects. The failure mode is fail-open-to-generic-error rather than fail-with-actionable-message.

## Truthiness check on subcategory

The branching condition is `if subcategory:` after `params.get("subcategory")`. This means:
- `params` absent or `{}` → `subcategory = None` → auto-select
- `params: {"subcategory": "addition_no_carry"}` → explicit path
- `params: {"subcategory": ""}` → auto-select (possibly surprising)

The empty-string case is unlikely in production since the TS handler no longer sends params at all, and the backward-compat path is for tooling or direct API calls. But if any caller passes `subcategory: ""` expecting it to mean "use the explicit path with defaults," they'll get auto-selection instead. Using `if subcategory is not None:` would make the intent explicit.

## Test coverage gaps

Six pytest tests cover: auto-selection with known child record, default to unit_order 1 when field missing, default when child not found, category propagation to prints table, explicit subcategory bypassing auto-select, and explicit subcategory with defaults. The vitest addition asserts the TS payload shape.

Not tested: DynamoDB `ClientError` in the auto-select path, `determine_next_problem` raising an exception, `current_unit_order` stored as a non-integer string.
