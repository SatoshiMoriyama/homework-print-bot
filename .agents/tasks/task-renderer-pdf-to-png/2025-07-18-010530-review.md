# PDF 経由 PNG 生成への切り替え — Renderer Lambda (v2)

Renderer Lambda を `page.screenshot()` から `page.pdf()` + `pdf-to-png-converter` パイプラインに切り替え、A4 ページ単位の複数 PNG 出力に対応した変更。v1 レビューで指摘した空ページガード欠如とテストカバレッジ不足は対応済み — `pngPages.length === 0` チェックの追加と、空配列・例外の両ケースのテストが加わった。

**Watch for:** `pngPages[i].content` が `undefined` のまま S3 に `PutObject` される可能性（confirmed — `PngPageOutput.content` は `Buffer | undefined` 型）。`networkidle0` による Lambda タイムアウトリスクは v1 から未対応のまま残存（likely）。

## High-level view

残存する懸念は 2 点。第一に `PngPageOutput.content` が型定義上 `Buffer | undefined` であり、`undefined` が S3 に書き込まれると 0 バイトの壊れた画像が LINE に送信される。第二に `networkidle0` への `waitUntil` 変更は v1 から変わっておらず、外部リソースを参照する HTML テンプレートでの Lambda タイムアウトリスクが残る。ただし後者は Puppeteer 側のデフォルト 30 秒タイムアウトで先にエラーになるため、致命度は v1 評価より低い。

v1 で指摘した部分アップロードのクリーンアップ欠如も残存している。現時点では S3 ライフサイクルルール等の外部対処で十分だが、ページ数の多い PDF で顕在化する可能性がある。

<details>
<summary>Issues (3)</summary>

1. **PngPageOutput.content undefined** — `pdf-to-png-converter` v4 の型定義では `content: Buffer | undefined`。ページ変換が部分的に失敗した場合 `undefined` がそのまま `PutObjectCommand.Body` に渡される。ループ内で `pngPages[i].content` の存在チェックを追加し、`undefined` ならエラーにすべき。(confirmed)
2. **networkidle0 タイムアウトリスク** — `waitUntil: "networkidle0"` は 500ms の無通信待機を要求する。現在のテンプレートでは問題にならない可能性が高いが、将来外部リソースを参照するテンプレートが追加されると Lambda の 60 秒タイムアウトに接近する。`page.setContent` に `timeout` オプションを付与するか `networkidle2` への切り替えを検討。(likely)
3. **部分アップロードのクリーンアップ欠如** — v1 から未対応。複数ページ中途で `PutObject` が失敗した場合、先行ページが S3 に孤立する。S3 ライフサイクルルールで TTL を設定するか、アップロード前にすべてのバッファを検証して fail-fast にする手がある。(likely)

</details>

## PngPageOutput.content の undefined リスク

`pdf-to-png-converter` v4.1.1 の型定義:

```typescript
export interface InMemoryPngPageOutput extends BasePngPageOutput {
    kind: 'content';
    content: Buffer | undefined;
    path: '';
}
```

現在のコード:

```typescript
for (let i = 0; i < pngPages.length; i++) {
    const putCommand = new PutObjectCommand({
      Body: pngPages[i].content,  // Buffer | undefined
    });
    await s3Client.send(putCommand);
}
```

AWS SDK の `PutObjectCommand` は `Body: undefined` を受け取ると 0 バイトオブジェクトを作成する。LINE に送信される「画像」が 0 バイト PNG になり表示エラーとなる。修正案:

```typescript
const content = pngPages[i].content;
if (!content) {
  throw new Error(`pdfToPng returned undefined content for page ${i + 1}`);
}
```

## networkidle0 の残存リスク

`page.setContent` のデフォルト `timeout` は 30 秒。Lambda タイムアウト（60 秒）到達前に Puppeteer 側で `NavigationTimeoutError` が発生し、`finally` ブロックで browser close → エラー伝播となる。失敗モードは「サイレントな Lambda タイムアウト」ではなく「明示的な例外」であり、致命度は v1 で評価したより低い。ただしリトライや呼び出し元のエラーハンドリング品質は `networkidle0` 起因のタイムアウト頻度に依存するため、テンプレートに外部リソースが追加された時点で再評価が必要。
