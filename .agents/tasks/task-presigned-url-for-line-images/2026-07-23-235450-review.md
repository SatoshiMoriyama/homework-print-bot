# Presigned URL utility for sending print images to LINE

The change adds an S3 presigned URL utility (`getPresignedUrl`) and a `sendPrintImage` function that combines URL generation with LINE's push-message API to deliver generated print images to users. Both original and preview URLs use the same presigned URL, which works for now but will need a separate thumbnail path eventually.

The `sendPrintImage` function includes try/catch error handling that logs failures with context (userId, s3Key) before rethrowing, providing observability at the delivery boundary. It has a documented integration point in the `print_request` handler flow: once the Print Generator Agent produces an S3 key, `sendPrintImage(userId, s3Key)` will be called.

Watch for:
- Presigned URL TTL of 6 hours (21600s) balances security exposure with LINE's image re-fetch behavior. LINE may still re-fetch after expiry for old chat history.
- `sendPrintImage` is exported and tested but not yet wired into the print_request flow. The integration point is documented in handler.ts; the Print Generator Agent will call it once it produces the S3 key.
- Same presigned URL used for both original and preview image. LINE clients download the full image for the thumbnail, which may become a bandwidth concern for large print images.

## High-level view

The presigned URL utility wraps `GetObjectCommand` + `getSignedUrl` with a configurable TTL defaulting to 6 hours (21600 seconds). The 6-hour window provides sufficient time for LINE to cache the image while limiting security exposure, since these are user-owned print images rather than sensitive data.

`sendPrintImage` reads `BUCKET_NAME` from the environment on every call, throwing a clear error if it is missing. The function uses `pushMessage` (not `replyMessage`), enabling asynchronous delivery outside the webhook request lifecycle. Error handling wraps the entire operation in try/catch, logging the error with structured context (userId, s3Key) before rethrowing, making delivery failures diagnosable from the caller.

The same presigned URL serves both `originalContentUrl` and `previewImageUrl`. LINE clients download the full image even for the thumbnail, which becomes a bandwidth concern once print images are large.

1. **Same URL for original and preview** - Using a full-resolution image as the preview forces LINE clients to download the full image for the thumbnail. Not a bug, but becomes a performance concern once print images are large or detailed.
2. **Presigned URL TTL vs LINE fetch timing** - The 6-hour TTL is a reasonable trade-off, but LINE may still re-fetch image URLs after expiry when a user scrolls back in very old chat history. Images will appear broken after the TTL expires.

## Presigned URL TTL and LINE's image lifecycle

The default TTL of 21600 seconds (6 hours) is set in `shared/s3.ts` via `DEFAULT_EXPIRES_IN` and used without override in `sendPrintImage`. The 6-hour window gives LINE ample time to cache the image on first delivery while limiting the window of access to the S3 object. The `expiresIn` parameter is configurable, so callers can pass a custom TTL if needed.

```typescript
const DEFAULT_EXPIRES_IN = 21600;
```

## sendPrintImage - delivery with error handling

The function wraps the entire presigned URL generation and push message flow in try/catch, logging errors with structured context before rethrowing:

```typescript
export async function sendPrintImage(userId: string, s3Key: string): Promise<void> {
  const bucketName = process.env.BUCKET_NAME;
  if (!bucketName) {
    throw new Error('Environment variable "BUCKET_NAME" is not configured');
  }
  try {
    const presignedUrl = await getPresignedUrl(bucketName, s3Key);
    const client = await getLineClient();
    await client.pushMessage(userId, {
      type: "image",
      originalContentUrl: presignedUrl,
      previewImageUrl: presignedUrl,
    });
  } catch (error) {
    console.error("Failed to send print image", { userId, s3Key, error });
    throw error;
  }
}
```

When called from the print-generation pipeline, failures from rate limits, invalid userIds, S3 errors, or network timeouts will be logged with enough context to diagnose issues.
